# Configuration

## The config file

dffy reads `$XDG_CONFIG_HOME/dffy/config`, which is `~/.config/dffy/config` when `XDG_CONFIG_HOME` isn't set. There's no file by default; every key has a built-in default.

Themes go in `themes/` next to it ([themes.md](themes.md)). dffy never writes to that directory, so it can live in a dotfiles repository.

```
# ~/.config/dffy/config
view = split
indicators = background
context = 5
keybind = ctrl+d=page_down
keybind = q=unbind
```

- One `key = value` per line. Spaces around `=` are optional, and a value can be wrapped in double quotes (`pager = "less -S"`).
- Lines starting with `#` are comments.
- An empty value (`theme =`) restores the default.
- A later line for the same key wins. `keybind` lines add up; [keys.md](keys.md) covers them.
- A line dffy can't use (an unknown key, a bad value) is skipped with a warning on stderr that names the file and line and suggests the closest key:

  ```
  warning: /home/me/.config/dffy/config:3: unknown key 'colour'
  hint: did you mean 'color'?
  ```

  The rest of the file still applies, and `dffy doctor` lists the same problems.

## Remembered settings

dffy remembers view settings you change in the viewer, such as the layout (`s`), wrapping (`W`) or a theme picked in the command panel, for the next run. The table above marks which settings it keeps.

The state file is `$XDG_STATE_HOME/dffy/state` (`~/.local/state/dffy/state` by default). dffy manages it:

- dffy rewrites it as you go;
- keys it doesn't know (from a newer dffy) are kept as they were;
- a file it can't read counts as empty.

For the viewer, a value comes from the first of these that sets it:

1. a flag on this run, such as `--split` (never remembered);
2. the last value you picked in the viewer;
3. the config file;
4. the default.

- Printed output, the pager and `--color-only` ignore remembered values, so scripts get the same output whatever was last picked in the viewer.
- Under 100 columns, a remembered split layout shows unified and a remembered tree doesn't open over the diff; both stay remembered. `--split` splits regardless, and `tree = show` in the config file opens the tree there.
- `remember = false` stops dffy from using or saving remembered values. To drop what's remembered, delete the state file.

## Where each value comes from

`dffy config` prints every setting as the viewer would run with it, each marked with its source, then the `keybind` lines that differ from the defaults:

```
$ dffy config
# config file: /home/me/.config/dffy/config
color = auto  # default
view = unified  # last used
wrap = true  # config
tab-width = 4  # default
...
keybind = q=unbind
```

The sources are `default`, `config`, `last used` and `flag`. They're comments, so the output works as a config file.

## Other files

| Path | What |
|---|---|
| `$XDG_CONFIG_HOME/dffy/config` | Your settings. dffy only reads it. |
| `$XDG_CONFIG_HOME/dffy/themes/` | Your themes. |
| `$XDG_STATE_HOME/dffy/state` | Remembered viewer settings, and whether the first-run tip was shown. |
| `$XDG_CACHE_HOME/dffy/` | Results that are slow to compute: rename passes, and highlighting and syntax diffs of large files. Shared by every dffy process, trimmed to `cache-size`. Safe to delete. |
| `$XDG_RUNTIME_DIR/dffy/` | The [watch broker's](watch.md#dffyd) socket. |
